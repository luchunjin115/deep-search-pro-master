# 跨境电商多 Agent 智能分析平台——产品需求与前端交互设计

> 文档状态：已确认  
> 版本：V1.1  
> 目标平台：开发者本地电脑、桌面端 Web  
> 首期市场：德国、法国 Amazon  
> 首期重点案例：橙色复古蘑菇台灯  
> 数据声明：业务数据均为明确标注的演示合成数据

## 1. 文档目的

本文档明确第一版产品解决什么问题、服务哪些用户、提供哪些功能，以及用户如何通过自然语言完成查询、研究、分析和报告生成。

本文档不描述底层代码实现；技术架构、数据库和评估方法分别见另外两份设计文档。

## 2. 产品定位

### 2.1 一句话定义

一个面向小型跨境电商团队的桌面端 AI 研究工作台，让用户通过自然语言同时使用企业数据库、内部知识库、互联网和用户文件，完成日常查询与复杂经营分析。

### 2.2 目标

第一版需要证明以下工程能力：

- 同一个聊天入口能够处理普通问答、库存查询、文件分析、图片理解和深度报告；
- Agent 能够根据任务自动选择正确的数据源和工具；
- 数据库、知识库、互联网和用户文件能够在同一任务中协同；
- 最终结论能够追溯到证据，区分事实、推断和未知信息；
- 长任务可以展示过程、失败原因和最终产物；
- 系统拥有可测试、可评估、可恢复和可扩展的工程边界。

### 2.3 非目标

第一版不追求：

- 接入真实 Amazon Seller Central 或 SP-API；
- 模拟真实销量预测工具并声称数据真实；
- 自动修改 Listing、广告或库存；
- 自动下单、付款、发邮件等外部写操作；
- 手机端完整适配；
- OCR 覆盖所有扫描文档；
- 本地部署大参数视觉模型；
- 多租户商业 SaaS 的完整计费体系。

## 3. 用户与权限

### 3.1 公司负责人

关注：

- 经营概览、利润、库存风险和新品机会；
- 德国、法国市场进入建议；
- 报告结论、风险和证据是否可信。

主要操作：

- 查看全公司数据；
- 发起跨数据源深度研究；
- 查看、导出报告；
- 查看高层指标和异常提示。

### 3.2 选品人员

关注：

- 商品外观、卖点、目标人群、价格区间和竞争差异；
- 供应商报价、成本、包装、物流和合规资料；
- 多张商品图和竞品图比较。

主要操作：

- 上传图片、报价单和产品规格；
- 搜索知识库与公开市场资料；
- 生成选品评分和立项报告；
- 查看产品、供应商和竞品数据。

### 3.3 Amazon 运营人员

关注：

- SKU 库存、Listing 信息、广告、销量和退货；
- 德语、法语关键词及商品表达；
- 日常快速查询和运营复盘。

主要操作：

- 查询被授权市场和产品数据；
- 分析评论、广告和销售数据；
- 上传运营表格；
- 生成周报、月报和 Listing 建议。

### 3.4 第一版权限矩阵

| 能力 | 公司负责人 | 选品人员 | Amazon运营 |
|---|---:|---:|---:|
| 查看经营汇总 | 全部 | 产品相关 | 负责市场 |
| 查看成本与供应商 | 全部 | 允许 | 默认隐藏敏感字段 |
| 查看库存与规格 | 全部 | 允许 | 允许 |
| 上传知识文件 | 允许 | 允许 | 允许 |
| 管理知识库文件 | 允许 | 自己上传/授权范围 | 自己上传/授权范围 |
| 发起深度报告 | 允许 | 允许 | 允许 |
| 管理用户和权限 | 允许 | 禁止 | 禁止 |

第一版虽然只有一个演示公司，也必须保留 `tenant_id`、`user_id` 和角色字段，证明数据隔离设计不是事后补丁。

## 4. 核心使用场景

### 4.1 快速业务查询

示例：

- “蘑菇灯现在还有多少库存？”
- “法国仓低于安全库存的 SKU 有哪些？”
- “这款灯的尺寸、电压和包装重量是多少？”
- “德国站上个月退货率最高的产品是什么？”

预期：优先查询企业数据库，数秒内返回简洁答案和数据时间范围，不启动不必要的多 Agent 研究。

### 4.2 内部知识问答

示例：

- “我们灯具供应商的质检标准是什么？”
- “知识库里有没有德国台灯合规检查清单？”
- “这份说明书对三档调光是怎么描述的？”

预期：使用自建 RAG，回答附带文档名、页码或分块定位；找不到时明确说明缺少证据。

### 4.3 用户文件分析

示例：

- 上传供应商报价 Excel：“比较这些报价并计算落地成本。”
- 上传 PDF：“总结其中的合规要求，并指出与蘑菇灯有关的条款。”
- 上传销售 CSV：“分析近六个月销量、广告和退货趋势。”

预期：文件先保存到本地存储，再解析、分析；用户能看到处理状态和失败原因。

### 4.4 商品图片理解

示例：

- 上传蘑菇灯图片：“提取可见的设计特点和使用场景。”
- 上传详情图：“识别图片里的尺寸、材质声明和开关信息。”
- 上传两组竞品图：“比较造型、颜色、场景图和信息表达。”

预期：千问多模态模型识别图片；输出必须区分：

- 明确可见：图片中直接观察到的事实；
- 合理推断：可能但不能确认的判断；
- 无法确认：认证、电气参数、隐藏结构等图片不能证明的信息。

### 4.5 跨数据源深度研究

示例：

> 结合蘑菇灯图片、供应商报价、公司现有 SKU、德国和法国公开市场资料，评估新品进入 Amazon 的可行性并生成报告。

预期：系统创建长任务，拆分为数据库查询、知识检索、互联网研究、数据分析和报告生成等步骤；用户可以离开当前会话并在任务中心查看进度。

## 5. 自然语言任务分级

系统不要求用户先选择“竞品分析”或“库存查询”，而是由路由器根据问题决定执行路径。

Tool（工具）是一次原子操作，例如“查询德国仓某个SKU的库存”；Skill（业务技能）是一套可复用的操作步骤，例如“完成一份库存风险分析”。两者都由系统根据自然语言自动选择，普通用户不需要理解这些技术概念，也不需要手动勾选工具或Skill。

| 任务等级 | 典型任务 | 执行方式 | 预期体验 |
|---|---|---|---|
| L0 普通对话 | 解释概念、询问系统能力 | 模型直接回答 | 流式、快速 |
| L1 单工具查询 | 库存、规格、单文档问答 | 单 Agent + 单工具 | 结果简洁 |
| L2 组合分析 | 数据库 + 文件、RAG + 图片 | 有限工具链 | 展示关键步骤 |
| L3 深度任务 | 选品、市场、经营报告 | Orchestrator + Workers | 后台运行、可恢复 |

路由结果不是不可改变的。执行过程中发现任务复杂度上升时，可以从 L1/L2 升级为 L3；升级需要在界面提示用户。

## 6. 信息架构

### 6.1 一级导航

- AI 工作台：聊天、上传、执行过程、证据和结果；
- 任务中心：运行中、等待确认、失败、完成的长任务；
- 企业数据：产品、库存、供应商、采购、销售、广告、退货；
- 知识库：文件、解析状态、索引状态、版本和权限；
- 报告中心：草稿、已完成报告、下载记录；
- 管理设置：用户、角色、模型、搜索和系统状态。

普通用户首次进入直接打开 AI 工作台，不要求先理解后台模块。

## 7. 前端视觉方向

### 7.1 设计主题

主题名称：**Evidence Workshop / 证据工坊**。

页面不是普通客服聊天框，而像一个产品研究员的数字工作台：左侧组织工作，中间进行对话和阅读，右侧整理证据。视觉语言来自首期产品的“橙色玻璃、镀铬金属、暖光与尺寸标注”，但整体保持企业工具的克制。

### 7.2 颜色令牌

| 名称 | 色值 | 用途 |
|---|---|---|
| Workshop Ink | `#17202A` | 主文字、导航 |
| Draft Paper | `#F6F8FA` | 页面背景 |
| Signal Orange | `#F26A2E` | 关键操作、当前证据、蘑菇灯识别色 |
| Evidence Blue | `#2E5D8A` | 网络与知识证据 |
| Verified Sage | `#557566` | 已验证、成功状态 |
| Rule Silver | `#D8DEE5` | 边界、分隔和表格线 |

橙色只用于动作和证据定位，不大面积铺背景，避免界面变成电商促销页。

### 7.3 字体

- 中文界面与正文：`Alibaba PuHuiTi 3`，无字体时回退 `Noto Sans SC`；
- 数字、SKU、任务ID、工具名：`IBM Plex Mono`；
- 报告标题：同一中文字体的较高字重，不额外引入装饰性衬线字体。

### 7.4 标志性交互：证据轨道

回答中需要证据支持的句子显示细小编号，例如 `[E3]`。鼠标悬停时，右侧证据轨道自动定位到对应来源，并显示：

- 来源类型：企业数据库、内部文件、用户文件、互联网、图片；
- 来源名称和时间；
- 原始片段或查询结果；
- 事实/推断/未知标签；
- 是否经过交叉验证。

这是产品最重要的视觉识别点，也是可信 Agent 与普通聊天机器人的核心差异。

## 8. AI 工作台布局

### 8.1 桌面端结构

```text
┌──────────────┬──────────────────────────────────┬──────────────────────┐
│ 一级导航      │ 会话与结果                        │ 证据轨道 / 任务详情    │
│              │                                  │                      │
│ AI工作台      │ 用户：分析这款灯是否适合德国站     │ E1 商品图片            │
│ 任务中心      │ [商品图缩略图]                    │ E2 企业数据库          │
│ 企业数据      │                                  │ E3 内部合规文档        │
│ 知识库        │ AI执行摘要                        │ E4 互联网来源          │
│ 报告中心      │ ┌ 查询企业数据      已完成 ┐      │                      │
│              │ ├ 检索合规知识      已完成 ┤      │ 当前选中：E3          │
│ 最近会话      │ └ 调研公开市场      运行中 ┘      │ [证据原文/数据预览]    │
│              │                                  │                      │
│              │ [流式回答、表格、图表、引用]        │                      │
│              │                                  │                      │
│              │ [ + 文件 ] 输入问题…… [发送]       │                      │
└──────────────┴──────────────────────────────────┴──────────────────────┘
```

建议宽度：

- 导航与会话栏：240px；
- 主内容：最小 640px，弹性扩展；
- 证据面板：360px，可折叠；
- 页面最小支持宽度：1280px。

### 8.2 输入区

输入区支持：

- 多行自然语言；
- 拖拽或选择图片、PDF、Word、Excel、CSV；
- 显示已附加文件及处理状态；
- `Enter`发送，`Shift + Enter`换行；
- 快捷入口只作示例，不限制用户问题：查询库存、分析图片、研究市场、生成报告。

禁止在输入区堆放过多模式开关。模型选择、检索条数、温度等技术参数放在管理设置，不暴露给普通业务用户。

当系统启用某个业务Skill时，默认只显示“正在分析库存风险”“正在比较供应商报价”等业务名称；Skill版本、允许工具和内部提示词仅在开发者调试模式显示。

### 8.3 回答内容块

一个回答可以组合：

- 普通文本；
- 事实摘要；
- 数据表格；
- 趋势图、对比图；
- 商品图片属性卡；
- 风险和未知项；
- 证据引用；
- 生成报告按钮；
- 下载附件。

回答底部提供：有帮助、无帮助、证据有误、结果过时四类反馈。

## 9. 任务中心

### 9.1 任务状态

统一状态机：

```text
queued → planning → running → waiting_for_user → synthesizing → completed
                         └──────────────→ failed
                         └──────────────→ cancelled
```

### 9.2 任务列表信息

- 任务标题和用户原始问题；
- 发起人和发起时间；
- 当前阶段和进度；
- 已调用的数据源；
- 已用时间；
- 是否需要用户确认；
- 失败原因和重试入口；
- 结果与报告入口。

进度不使用虚假的百分比。若无法准确估算，显示“3/6个计划步骤完成”和当前步骤。

### 9.3 长任务过程展示

普通用户看到业务化步骤，例如：

- 正在读取供应商报价；
- 正在查询现有灯具成本；
- 正在检索德国合规资料；
- 正在对比公开市场信息；
- 正在汇总结论。

开发者调试模式才显示 Agent 节点名、工具名、Token和原始参数。

调试轨迹还可以显示本次自动选择的Skill及版本、工具是否被Harness允许或拒绝。Harness是包在Agent外层的运行时护栏，负责权限、超时、调用次数和审计；这些信息不进入普通用户的主界面。

## 10. 文件与图片交互

### 10.1 本地存储决策

第一版使用本地文件系统，路径只由服务端管理。前端和模型只接触 `file_id`，不接触 Windows 绝对路径。

文件存储接口保留未来 S3/MinIO 适配能力，但 MinIO 不进入第一版必需部署组件。

### 10.2 文件处理状态

```text
uploaded → validating → parsing → indexing → ready
                              └──────→ failed
```

状态卡必须告诉用户：

- 当前处理到哪一步；
- 哪些页、工作表或图片成功；
- 失败原因；
- 是否可以重试；
- 文件是否已经进入知识库。

### 10.3 文件安全要求

- 使用 UUID 作为实际存储名；
- 保留原文件名作为元数据；
- 校验文件大小、扩展名和 MIME；
- 计算 SHA-256，识别重复文件；
- 限制访问在应用数据目录内；
- 下载接口使用 `file_id`；
- 删除采用软删除，物理清理由后台任务完成。

## 11. 关键交互流程

### 11.1 库存查询

```text
用户：橙色蘑菇灯德国仓还有多少库存？
→ 路由为快速业务查询
→ 调用只读库存工具
→ 返回可售、在途、安全库存和数据日期
→ 引用企业数据库记录
```

不生成长报告，不调用互联网和知识库。

### 11.2 图片加数据库分析

```text
用户上传商品图：分析这款灯，并查找公司类似SKU
→ 图片保存并验证
→ qwen3.8-max提取视觉属性
→ 属性通过JSON Schema校验并保存
→ 调用产品相似查询工具
→ 返回图片观察、相似SKU和未知项
```

### 11.3 深度选品报告

```text
用户：评估蘑菇灯进入德国和法国Amazon的可行性
→ 系统识别为L3任务并创建任务卡
→ 生成可编辑计划
→ 并行检索企业数据、知识库和公开信息
→ 运行成本和情景分析
→ 汇总结论、风险、证据和未知项
→ 生成Markdown与PDF报告
```

若关键条件缺失，例如没有采购价，系统应暂停并询问，或者明确使用假设值，不能悄悄编造。

## 12. 异常与空状态

| 场景 | 界面表达 | 可执行动作 |
|---|---|---|
| 数据库无记录 | “没有找到符合条件的库存记录” | 修改市场/SKU条件 |
| 知识库无证据 | “现有知识库无法支持该结论” | 上传文件/允许网络搜索 |
| Tavily不可用 | “公开信息搜索暂时不可用” | 重试/基于已有证据继续 |
| 模型超时 | “模型响应超时，任务已保留” | 从检查点重试 |
| 文件解析失败 | 显示具体文件和失败环节 | 重新上传/跳过该文件 |
| 权限不足 | 说明缺少哪类权限 | 联系管理员 |
| 部分成功 | 返回已完成结果并列出缺失项 | 重试失败步骤 |

错误提示使用事实描述，不使用“未知错误”“出问题了”等无帮助文字。

## 13. 非功能需求

### 13.1 性能目标

- 普通页面操作应在 300ms 内提供可见反馈；
- 快速查询目标 P95 小于 8 秒；
- 首个流式文本目标小于 3 秒；
- 深度任务允许分钟级执行，但必须在 2 秒内返回任务ID；
- 文件上传显示实时进度；
- 具体验收阈值在基线评估后调整。

### 13.2 可用性

- 键盘可完成发送、打开附件和关闭面板；
- 所有交互元素有清晰焦点状态；
- 状态不只依赖颜色；
- 尊重 `prefers-reduced-motion`；
- 图表同时提供数据表入口。

### 13.3 可解释性

每次有工具参与的回答至少显示：

- 使用了哪些数据源；
- 数据时间；
- 关键引用；
- 哪些结论是推断；
- 哪些信息仍未知。

### 14.3 产品验收场景

至少通过以下演示：

1. 运营人员用一句话查询德国仓库存；
2. 选品人员上传蘑菇灯图片，获得结构化属性和未知项；
3. 上传供应商报价 Excel，完成成本对比；
4. 查询内部合规资料，回答包含定位引用；
5. 发起德国、法国市场选品任务，系统调用不少于三类数据源；
6. 报告展示数据、引用、风险和假设并可下载；
7. 用户无权访问的数据在数据库查询和RAG检索两层均被拦截；
8. 任一外部服务失败时，任务不会静默丢失。

## 15. 设计决策记录

| 决策 | 结论 | 原因 |
|---|---|---|
| 主要交互 | 自然语言聊天工作台 | 用户任务不固定，不能只做竞品分析表单 |
| 产品案例 | 蘑菇灯作为重点案例，不绑定系统 | 有真实业务语境，同时保留扩展性 |
| 模型 | 千问负责推理与多模态 | 减少双模型信息传递，支持图片和工具调用 |
| 文件存储 | V1本地存储 | 优先完成高含金量Agent主链路 |
| 过程展示 | 业务步骤 + 可选调试轨迹 | 兼顾业务易用性和工程展示 |
| Skill交互 | 自然语言自动触发，普通用户不手动选择 | 保持聊天入口简单，同时复用复杂业务流程 |
| Harness展示 | 普通用户只看业务状态，调试模式看策略与轨迹 | 安全控制必须由后端执行，界面只负责解释结果 |
| 视觉签名 | 证据轨道 | 把可信度和引用变成核心交互，而非装饰 |
