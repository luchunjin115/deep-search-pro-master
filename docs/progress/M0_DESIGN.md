# M0：项目整体方案设计与协作基线

> 阶段状态：已完成  
> 开始日期：2026-08-27  
> 完成日期：2026-08-28  
> 最近更新：2026-08-28

## 1. 阶段目标

- 确定产品范围、目标用户与前端交互；
- 确定系统、Agent、RAG和数据架构；
- 确定模拟数据、评估体系和实施路线；
- 建立教学式协作和进度记录规则。
- 确定Skill、Tool、Harness和MCP的职责边界及分阶段路线。

## 2. 阶段完成标准

- 三份总体设计文档得到用户明确确认；
- 核心技术选型和V1边界没有冲突；
- 后续开发必须先提交阶段方案，再按可验证的小步骤推进；
- 已建立持久化的协作规则和分阶段进度记录机制。
- 业务Skill、Agent Tool、Harness和MCP边界在设计文档、实施计划与项目规则中一致。

### 2026-08-28｜M0-04｜同步Skill、Tool、Harness与MCP架构决策

**状态：已完成**

**目标**

把已讨论确认的能力分层正式写入项目基线，避免后续把简单Tool包装成复杂Skill、把Harness误做成Agent，或为了增加技术数量过早引入MCP。

**修改文件**

- `AGENTS.md`：将Skill、Tool、Harness和MCP边界加入长期项目约束。
- `docs/design/01_Product_Requirements_and_UX_Design.md`：明确用户仍通过自然语言自动触发能力，以及普通界面和调试界面的展示差异。
- `docs/design/02_System_Architecture_and_Agent_RAG_Design.md`：补充4项ADR、约13个Tool、5个业务Skill、Harness组件、权限交集和MCP边界。
- `docs/design/03_Data_Evaluation_and_Implementation_Plan.md`：把这些能力分配到M1至M5，并增加Skill和Harness评估要求。
- `docs/PROJECT_PROGRESS.md`：在总看板记录新增关键决策和本次完成事项。
- `docs/progress/M0_DESIGN.md`：记录本次设计基线变更及验证结论。

**调用链位置**

本步属于产品、架构和项目治理层，没有修改“前端 → API → Schema → Service → Model → PostgreSQL”运行代码。它为后续链路规定：前端只提供自然语言入口；API创建带身份的RunContext；Schema约束Skill和Tool输入输出；Service/Harness执行权限、预算和审计；Model只提出选择与参数；PostgreSQL保存业务数据、证据和轨迹。

**验证方法与实际结果**

- 检查三份设计文档版本均更新为V1.1；
- 检查架构文档同时包含5个约定业务Skill、13个目标Tool和Harness权限交集公式；
- 检查实施文档在M1至M5均有对应落地或评估步骤；
- 检查V1不引入MCP、确定性PDF转换属于Service、每次只暴露1至5个Tool等表述没有互相冲突；
- 检查5份相关Markdown的代码围栏均成对闭合，未发现合并冲突标记；
- PowerShell脚本从架构文档7.2实际提取到13个Tool，从7.5实际统计到5个Skill；
- `git status --short`显示当前仓库文件均未被Git跟踪，因此`git diff --check`没有检查到这些文件；本次不把它作为有效格式证明，并把这一限制补充到M0-03历史验证中。

**能够证明**

- Skill、Tool、Agent、LangGraph、Harness和MCP的职责边界已经形成一致的书面基线；
- 5个Skill不会在M1一次性实现，而是从M3开始逐步落地；
- 后续可以按里程碑开发并为Skill选择、权限和执行轨迹建立评估。

**不能证明**

- Skill加载器、Tool注册表或Harness运行代码已经实现；
- 千问能够正确选择Skill和Tool；
- 权限、预算、Checkpoint或故障恢复已经通过运行测试；
- 约13个Tool是永久不变的最终数量，具体Schema仍需在对应阶段确认。

**问题与风险**

- 后续实现可能重新出现“Service也包装成Tool”的边界漂移；优先对照架构文档7.2和7.4检查单一职责与是否需要模型决策。
- `SKILL.md`写得过长会占用上下文；优先检查是否能把参考资料和模板拆到`references/`与`assets/`并采用渐进式加载。
- 只在Prompt中写工具白名单不能提供真正安全；出现越权时优先排查Harness服务端的权限交集与ToolRegistry，而不是只改提示词。

**下一步**

创建M1阶段文件并提交库存查询垂直切片的详细实施方案；M1只建设最小Harness和两个Tool，不提前实现Skill运行时。
